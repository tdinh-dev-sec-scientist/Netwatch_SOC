# Pack format (`netwatch-bench/pack/v0`)

A pack is a directory with a `pack.yaml` (or `pack.json`): the captures to
replay, and the answer key to score them against. Nothing in it is specific to
an engine. Attacks are described by addresses, time windows and MITRE ATT&CK
techniques, so NetWatch, Suricata and anything else are graded against the
same key. Back to [NetWatch Bench](../../netwatch_bench/README.md).

```yaml
schema: netwatch-bench/pack/v0
id: my-lab-2026-q4                 # short identifier
title: Lab capture, Q4 2026
description: What this pack is for.
source:                            # where the traffic came from; shown in reports
  name: My lab
  license: CC-BY-4.0
internal_networks: [10.0.0.0/8]    # default: RFC 1918, loopback, link-local

captures:                          # one per monitored host (sensor)
  - id: web01
    hosts: 1                       # multiplies host-hours; default 1
    files:
      - path: captures/web01.pcap  # relative to the pack directory
        sha256: 9f86d0...          # optional; checked when present
  - id: big-dataset-host
    files:
      - data_path: day1/host.pcap  # relative to --data, for corpora too
                                   # large for the repository

scenarios:                         # the answer key
  - id: ssh_brute
    label: SSH brute force from the red team box
    techniques: [T1110]            # what a correct detection is tagged with
    attackers: [203.0.113.5]
    victims: [10.0.0.12]
    windows:                       # ISO 8601 (Z or offset; naive = UTC) or epoch
      - [2026-10-01T14:00:00Z, 2026-10-01T14:30:00Z]
    onset: 2026-10-01T14:05:00Z    # labelled start, for latency; optional

  - id: lateral
    label: Scanning from a compromised workstation
    techniques: [T1046, T1021]
    attackers: [198.51.100.7]
    victims: [10.0.0.40]
    pivot: 10.0.0.40               # alerts from here to internal hosts count
    windows: [[2026-10-01T15:00:00Z, 2026-10-01T16:00:00Z]]

  - id: botnet
    label: Botnet C2 polling
    techniques: [T1071.001]
    attackers: [192.0.2.80]
    victims: [10.0.1.1, 10.0.1.2]
    per_victim: true               # each victim is scored separately
    windows: [[2026-10-01T09:00:00Z, 2026-10-01T18:00:00Z]]

annotations:                       # known activity the labels leave out
  - id: internet_rdp_scanning
    label: Unlabelled internet RDP scanning
    techniques: [T1595]
    attackers: [192.0.2.10, 192.0.2.11]
    victims: [10.0.0.12]
    windows: [[2026-10-01T00:00:00Z, 2026-10-02T00:00:00Z]]

limitations:                       # repeated in every report on this pack
  - One small lab network; benign traffic is two hours of office use.
```

## Rules

- Every scenario needs at least one technique, one victim, one window, and
  attackers, a pivot, or both. Windows must end after they start.
- Techniques are ATT&CK ids (`T1110`, `T1499.002`). A scenario listing a
  parent technique accepts its sub-techniques; listing a sub-technique accepts
  only that sub-technique.
- `id`s are unique within captures, and within scenarios plus annotations.
- `netwatch-bench validate PACK [--data DIR]` checks all of this and that
  every capture file can be read.

## Writing good ground truth

- **Derive labels from the packets, not only from a schedule.** The demo pack
  dropped its XSS scenario because the slice, cut from the dataset's
  published schedule, turned out to contain no attacker packets at all.
- **Pad windows a little, then record the onset.** Padding absorbs clock skew
  and slow detections; `onset` keeps latency honest.
- **Keep benign traffic in the pack.** Without it, an engine that alerts on
  everything scores perfectly.
- **Keep a held-out pack.** Tune on one pack, report on another that was not
  replayed until the rules were frozen.

The CSE-CIC-IDS2018 packs in `packs/` are generated by
`eval/cicids2018/export_packs.py` from the original truth files.
